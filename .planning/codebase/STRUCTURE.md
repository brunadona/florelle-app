## Directory Purposes

**Root Directory:**
- Purpose: Main PWA application entry point and assets
- Contains: Single-file app, worker backend, PWA config, icons
- Key files: `index.html` (everything), `worker.js` (API)

**.git/**
- Purpose: Version control repository
- Contains: Commit history, branches, tags
- Note: Repository at GitHub `brunadona/florelle-app`

**.claude/**
- Purpose: Claude Code configuration and development tools
- Contains: Pre-commit hooks, git worktrees for parallel development
- Not deployed: Stays local, not in GitHub

**.planning/codebase/**
- Purpose: Architecture and structure documentation for GSD system
- Contains: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md
- Generated by: `/gsd-map-codebase` command with different focus areas
- Used by: `/gsd-plan-phase` and `/gsd-execute-phase` to understand codebase patterns

**docs/superpowers/**
- Purpose: Project documentation and planning
- Contains: Feature specs, implementation plans, design decisions
- Pattern: Dated files for tracking iterations (e.g., `2026-07-21-kommo-followup-tasks-design.md`)

## Key File Locations

**Entry Points:**
- `index.html`: Main application file. Browser loads this, parses HTML, executes inline `<script>` tag. Page registration and initialization at lines 6200+.
- `manifest.json`: PWA manifest defining app name, icons, start URL, display mode (standalone)

**Configuration:**
- `index.html` lines 1489-1508: Column definitions (COLS array), product labels (PLABEL), pricing (PRECO_SUGERIDO), payment types (PAGLABEL)
- `index.html` line 5007-5008: Google OAuth constants (GD_CLIENT_ID, GD_SCOPE)
- `index.html` line 5110: Cloudflare Worker endpoint (const _WK)
- `worker.js` lines 1-30: Worker setup, CORS headers, token generation

**Core Logic:**
- `index.html` lines 1527-1574: Storage operations (load, save, migrate)
- `index.html` lines 1598-5100: Business logic (rendering, filtering, modal management, integrations)
- `index.html` lines 5112-5300: Cloud sync (Google Drive, Cloudflare Worker)
- `worker.js`: API routes for contract signing, data sync, analysis

**Testing & Development:**
- `seed.js`: Generates sample bride data for testing (line 1-200)
- `florelle_test.js`: Test suite (30KB file, 1000+ lines)
- `stress-test.js`: Performance testing with large datasets

**PWA/Browser:**
- `sw.js`: Service worker. Cache-busting strategy (deletes all caches on activation, forces network fetch).
- `manifest.json`: Declares app name, icons, theme colors, start URL

## Naming Conventions

**Files:**
- `.html` for UI markup
- `.js` for JavaScript code
- `.json` for configuration/data
- `.png` for raster images
- `[name]-test.js` or `[name].test.js` for test files
- Example: `index.html`, `worker.js`, `seed.js`, `florelle_test.js`

**Directories:**
- Lowercase with hyphens for multi-word names: `.planning/codebase`, `docs/superpowers`
- Logical grouping by feature/concern: `docs/superpowers/specs`, `docs/superpowers/plans`
- `.git`, `.claude`, `.planning` as conventions for meta-directories

**HTML IDs (DOM Elements):**
- Single-letter prefix + descriptive name: `#hd` (header), `#kw` (kanban wrapper), `#kb` (kanban board), `#si` (search input), `#ov` (overlay modal)
- Abbreviations: `#kcs` (kanban column scroll), `#kct` (kanban column title), `#kcc` (kanban column count)
- Form fields: `#m-*` prefix for modal fields (`#m-nome`, `#m-telefone`, `#m-data-casamento`)
- Drive/sync: `#sync-btn`, `#sync-dot`, `#sync-lbl`
- Example pattern: `g('hd')` = get header element

**CSS Classes:**
- Lowercase with hyphens for compound words: `.bcard` (bride card), `.kcol` (kanban column), `.kcs` (kanban column scroll)
- Single-letter abbreviations for common prefixes: `.b*` (button), `.k*` (kanban), `.c*` (card), `.p*` (pill), `.d*` (date)
- State modifiers: `.hidden`, `.active`, `.muted`, `.dov` (drag-over), `.drag`
- Semantic: `.bprim` (button primary), `.bbel` (button bell), `.badd` (button add)
- Example: `<div class="bcard">` = bride card element

**JavaScript Functions:**
- camelCase for public functions: `renderAll()`, `openModal()`, `saveModal()`, `syncKommo()`
- Leading underscore for private/internal: `_buildProdFilter()`, `_cloudPush()`, `_nomeDisp()`, `_analyzeAndFill()`
- Verb-first for actions: `load()`, `save()`, `sync()`, `build*()`, `render*()`
- Toggle/check verbs: `toggle*()`, `is*()`, `has*()`
- Example: `_queueCloudSync()` is internal function to queue deferred sync

**JavaScript Variables:**
- camelCase for locals: `newBride`, `formData`, `syncStatus`
- Global state: UPPERCASE for constants, UPPERCASE or camelCase for globals
- Prefixed for tracking: `_gToken` (Google token), `_mDriveFolder` (modal Drive folder), `_syncSt` (sync status)
- Array/collection suffixes: plurals or `List`/`Map`: `DATA`, `COLS`, `mRem` (modal reminders), `mAnexos` (modal attachments)
- Example: `const uid=Date.now().toString(36)+Math.random().toString(36).slice(2,9)` — unique ID generator

**Data Field Names (Bride Object):**
- Portuguese with camelCase: `id`, `crd` (created), `nome`, `telefone`, `dataCasamento`, `endereco`, `produto`, `formaPagamento`, `statusEmbalagem`, `etapa`, `valorTotal`, `anotacoes`, `lembretes[]`, `pagamentos[]`
- Abbreviated date fields: `dataSilica`, `dataEntregaEmbalagem`
- Flags: prefixed with `autoriza*`: `autorizaReposicao`
- External IDs: prefixed with underscore: `_kommoId`, `_googleFolderId`
- Nested objects: `reserva{}`, `bride.contrato` (HTML string)

**API Endpoints (Cloudflare Worker):**
- Lowercase REST paths: `/data`, `/sign`, `/contract/:brideId`, `/pending-confirm`, `/analyze-wa`, `/kommo`
- HTTP verbs: GET for retrieval, POST for creation/processing
- Query params: `?_=` for cache-bust, `?q=` for search
- Example: `POST https://florelle.brunadonaa.workers.dev/sign` → save contract, get token

## Where to Add New Code

**New Feature (e.g., SMS notifications):**
- Primary code: Add function to `index.html` in business logic section (~2000-5100)
- Example: `async function sendSMS(brideId, msg) { ... }`
- Handler: Attach click handler to new button in UI (~17-730), e.g., `onclick="sendSMS('${b.id}')"`
- Backend: If needed, add route to `worker.js`, e.g., `if (url.pathname === '/sms') { ... }`
- Testing: Add test case to `florelle_test.js`

**New Column/Stage (e.g., "Aguardando pagamento de entrada"):**
- Config: Add object to `COLS` array at line 1489-1500
- Example: `{id:'aguardandoPag',label:'Aguardando pagamento',color:'#...'}`
- Rendering: No code change needed (auto-renders from COLS)
- Filtering: If filtering by stage exists, auto-includes new stage
- Styling: Kanban styling already handles dynamic columns

**New Integration (e.g., WhatsApp Business API):**
- Frontend: Add UI in appropriate modal section (~1000-2000)
- Example: Add button "Enviar via WhatsApp Business API"
- Worker: Add POST route in `worker.js`, e.g., `/send-wpp-msg`
- Example: `if (request.method === 'POST' && url.pathname === '/send-wpp-msg') { ... }`
- Call: Invoke from frontend via `fetch(_WK + '/send-wpp-msg', { method: 'POST', body: JSON.stringify(...) })`

**New Modal/Form Section:**
- HTML: Add `<div class="modal-section">...</div>` in modal structure (~1000-1400)
- Naming: Use `m-` prefix for input IDs: `<input id="m-wpp-template">`
- Styling: Add CSS rules in `<style>` tag (~17-730)
- Handler: Add click/change handler function: `function m_handleChange() { ... }`
- Sync: Add field to `fillForm()` (~2013) and `saveModal()` (~2222)

**New Report/View:**
- Tab Navigation: Add tab button to header (~1000-1400 in HTML)
- Tab ID: Assign unique `curTab` value, e.g., `curTab='sms'`
- Render Function: Create `renderSMS()` function, called by `renderAll()` when `curTab==='sms'`
- HTML Container: Add `<div id="sms-panel">` to hold content
- Example: Look at `renderReports()`, `renderFinancialTab()`, `renderTasks()` as patterns

**New Data Field in Bride Object:**
- Field Name: Use camelCase Portuguese: `telefoneEmergencia`, `dataUltimoPagamento`
- Migration: Add to `migrateOld()` function (~1527) if migrating from v2
- Persistence: Included automatically in `DATA` array via `save()` → localStorage
- Form: Add input in modal, sync in `fillForm()` and `saveModal()`
- Default: Bride objects auto-include all fields set during creation

**Utilities/Helpers:**
- Shared utilities: Add near top with other helpers (~1577-1596)
- Examples: `uid()`, `today()`, `fmt()`, `daysTo()`, `esc()`, `g()`, `gv()`
- Pattern: Keep utilities stateless and reusable
- Testing: Add to `florelle_test.js` with examples of expected input/output
